# 小窗口性能优化实施计划

日期：2026-10-17。范围：DBX 独立胶囊窗口及共用文字滚动；不使用 Aegis skills。

## 目标与现状

`surface: window` 已关闭 Stage 帧门，但仍执行完整 `startApp`，初始化曲库、账号、推荐和创意界面；每份播放快照还更新隐藏界面。文字实际每 400ms 移动，却用永久 rAF 测量两个文字窗口。目标是减少启动请求、持续 DOM 操作和空转回调，保持暂停/继续、上下首、封面、错误提示、系统媒体键、重连和展开主界面可用。

## 实施顺序

- [x] 1. 文字滚动按需调度：测量只发生在内容/尺寸/字体变化后；400ms 定时推进，由 CSS 补间。短文本、隐藏页面、关闭滚动时不保留循环；恢复后重新测量。
- [x] 2. 小窗口只更新可见状态：共用播放命令和当前曲目解析；跳过隐藏界面快照、频谱、歌词和节拍诊断，保留错误、结束、缓冲和换源处理；避免重复设置原生窗口尺寸。
- [x] 3. 小窗口走精简启动：提前识别窗口实例，复用胶囊交互初始化，只恢复主题/动效设置、当前状态与队列；不初始化布局皮肤、搜索、账号、推荐、舞台和设置面板。不另建播放实现。完整窗口保持原路径。
- [x] 4. 回归与记录：零依赖调度/状态测试加入前端检查；真实浏览器模拟 DBX 桥并记录请求、回调、DOM 修改，结合单元测试覆盖高刷、隐藏恢复、深浅/自定义主题、封面竞态、本地/在线/播客、命令失败、重连、恢复队列和展开顺序；执行现有前端和胶囊布局检查。

## 边界与验收

- 用户已有的 README、产品/技术路线图等未提交修改不属于本任务。
- 本轮仍加载共用 HTML/脚本，不能声称内存降到独立极简页面水平。
- 共享 sidecar 仍广播事件；在窗口消费处跳过无用事件。本轮不新增后端订阅协议、不改音频解码/DSP/FFT。
- 以相同浏览器、曲目、桥数据对比改动前后启动 API 数量、10 秒空闲/长文本的回调与 DOM 操作；不将这些指标冒充 macOS 原生 CPU/内存实测。
- 短文本稳定后无轮播定时器/rAF；长文本约 2.5 次/秒推进，隐藏或减少动效时停止；状态突发不写隐藏播放 UI。
- 小窗口启动无曲库列表、账号探测、推荐、歌词、节拍、设备与浮层钥匙请求；暂停、上下首、恢复/重连、错误和展开均通过回归。

## 实施结果

实现入口：`app.js` 的 `startFloatingCapsule` / `refreshFloatingCapsule` 提供精简启动及重连；`initCapsuleControls` 为两种入口共用。播放仍走 `setPlayback` 和传输层的串行命令，曲目仍走 `loadNowPlaying`。当前曲目请求增加代次校验，封面使用已有的一次性赋值管线，防止换曲后的迟到回填。在线详情和封面共用一次详情请求。

`ThemeStudio.initPalette` 只恢复自定义配色及注册主题；浮窗的 DOMContentLoaded 跳过在线歌单自启动。系统媒体键保留播放、暂停、停止、上下首和定位，定位使用快照时间；常规播放位置向系统每秒同步，播放态变化立即同步。

### 浏览器对比

完整生产 HTML/脚本，模拟 DBX 桥调用隔离的真实 Rust 服务；同一首暂停的测试 WAV，每秒注入 50 个状态事件与 30 个频谱事件。内容变更引发的首次布局完成后，各采样 10 秒。原生尺寸请求只记录，不实际调整操作系统窗口。

| 指标 | 改动前 Chromium | 改动后 Chromium | 改动后 WebKit |
| --- | ---: | ---: | ---: |
| 启动桥请求 | 31 | 5 | 5 |
| 短文本滚动回调 / 10 秒 | 607 rAF | 0 | 0 |
| 长文本滚动回调 / 10 秒 | 608 rAF | 25 定时回调 | 25 定时回调 |
| 短文本布局宽度读取 / 10 秒 | 3642 | 0 | 0 |
| 长文本布局宽度读取 / 10 秒 | 3648 | 0 | 0 |
| 短文本隐藏主界面 DOM 修改 / 10 秒 | 2019 | 0 | 0 |
| 长文本隐藏主界面 DOM 修改 / 10 秒 | 2012 | 0 | 0 |
| 截至长文本采样结束的原生尺寸请求 | 3 | 1 | 1 |

5 个启动请求是设置、播放状态、当前曲目详情、队列及事件订阅。在线曲目可能另需详情及封面代理；恢复播放模式也可能额外写入模式，不能把 5 作为所有曲目的固定上限。原始记录在 `output/playwright/capsule-performance/{chromium-before,chromium-after,webkit-after}.json`（本地产物，Git 忽略）。

### 验证

- `node scripts/check-frontend.js`：46 步通过，已包含新增的 `check-capsule-performance.js`。
- `node scripts/check-player-races.js`：9 项播放串行及竞态回归通过。
- `node scripts/check-theme-studio.js`：主题工坊回归通过。
- `check-capsule-performance.js`：模拟 144Hz 下布局不重复读取、隐藏/减少动效/尺寸恢复、事件突发、播放缓冲及错误、曲源接力、本地/在线/播客元数据、封面和详情乱序、恢复队列游标、精简重连、系统媒体键和原生尺寸失败重试。
- `check-capsule-performance-browser.js`：Chromium、WebKit 均通过；除采样指标外，覆盖真实播放/暂停、上下首请求、命令失败回滚、提示、先展开再关窗、隐藏/动效恢复、字体/宽度变化，以及深色、浅色、自定义和二次元主题的整页重载恢复。
- `check-capsule-browser.js`：两种引擎各 36 组，共 72 组皮肤 × 主题 × DPR 布局通过。

复现浏览器检查需设置 `PLAYWRIGHT_MODULE`，WebKit 加 `CAPSULE_BROWSER=webkit`，然后分别运行 `node scripts/check-capsule-performance-browser.js` 与 `node scripts/check-capsule-browser.js`。`CAPSULE_AUDIT_BASELINE=1` 用于修改生产代码前记录基线，不能在优化后的代码上生成旧版本基线。

以上证明前端初始化和持续 UI 工作减少；当前环境为 Windows，未测量 macOS 原生宿主的 CPU、GPU、内存或耗电。仍加载共用脚本、HTML 和共享播放服务，后续如需继续降低内存，应单独评估极简页面与资源拆包。
